# ops_dashboard — 다컴스 운영 대시보드

채용 리드·타겟 기업 CRM·카드뉴스 성과를 한 곳에서 보고, 타겟 기업 CRM은 직접
편집하기 위한 두 가지 방법. **컴퓨터에 이 저장소를 내려받지 않고 전부
채팅으로만 다루는 경우 A(구글 시트)를 쓴다.**

## A. 구글 시트 (설치 없음, URL 하나로 접근)

`sync_sheet.py`가 저장소 데이터와 구글 시트 사이를 동기화한다. 시트 자체가
곧 "다 펼쳐서 보는" 화면이고, 브라우저에서 시트를 열어 셀을 고치면 그게 곧
편집이다 — 별도 웹앱이 없다.

**최초 설정 (한 번만)**
1. 구글 시트를 새로 만들고, 서비스 계정 이메일을 편집자로 공유
2. 저장소에 서비스 계정 키를 저장 (`card_news_pipeline/service_account.json`,
   git에 커밋되지 않음)
3. 최초 시딩:
   ```bash
   SPREADSHEET_ID=<시트ID> python3 ops_dashboard/sync_sheet.py push
   ```

**평소 사용**
- 시트 링크를 북마크해두고, "타겟기업" 탭에서 컨택 상태·다음 액션·메모를
  자유롭게 편집한다. "채용리드"/"카드뉴스성과" 탭은 참고용(읽기 전용) —
  거기서 고쳐도 다음 `push` 때 사라진다.
- `cold-email-team` 서브에이전트를 돌리기 전에는 항상
  `python3 ops_dashboard/sync_sheet.py pull`로 시트의 최신 편집 내용을
  `data/target_companies.csv`로 가져온다(에이전트 지침에 이미 명시됨).
- 최신 리드/카드뉴스 성과를 시트에 반영하려면 `push`를 다시 실행한다
  (예: job_pipeline·metrics_pipeline을 새로 돌린 뒤).

**주의**
- 실시간 동기화가 아니다 — 마지막 push/pull 시점 기준이다.
- 서비스 계정 키(`service_account.json`)는 구글 클라우드 계정 권한 그
  자체다. 유출 의심 시 구글 클라우드 콘솔에서 즉시 키를 폐기하고 새로
  발급한다.

## B. 로컬 서버 (컴퓨터에 저장소를 내려받고 Python이 있는 경우)

```bash
python3 ops_dashboard/server.py
# → http://127.0.0.1:8787 브라우저 자동으로 열림
```

채용 리드·타겟 기업 CRM·카드뉴스 성과·7개 서브에이전트 실행 현황(구글
시트에는 없는 자동화 실행 현황까지)을 한 페이지에서 본다. 표준 라이브러리만
사용해 별도 설치가 필요 없다.

| 탭 | 데이터 소스 | 편집 가능? |
|---|---|---|
| 채용 리드 | `data/dashboard.json` | 읽기 전용 |
| 타겟 기업 CRM | `data/target_companies.csv` | **편집 가능** (즉시 파일에 저장) |
| 카드뉴스 성과 | `data/card_news_metrics.csv` | 읽기 전용 |
| 자동화 실행 현황 | `outputs/<team>/latest.json` | 읽기 전용 |

인증이 전혀 없으므로 `127.0.0.1`에서만 열고, 절대 외부 네트워크에 노출하지
않는다.

## A와 B를 같이 쓸 때 주의할 점

두 방식은 같은 파일(`data/target_companies.csv`)을 공유하지만 자동으로
서로 동기화되지 않는다. 로컬 서버로 편집했다면 그 변경을 시트에 반영하려면
`push`를, 시트로 편집했다면 로컬에 반영하려면 `pull`을 실행해야 한다.
동시에 두 곳에서 편집하지 않는다(마지막에 실행한 쪽이 이긴다).
